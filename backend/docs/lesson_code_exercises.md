# Кодовые блоки уроков

```markdown
:::code python
id: python-first
:::

:::code sql
id: sql-first
:::
```

Директивы располагаются с начала строки, вне fenced code. Внутри блока
допустима только строка `id:` (1–64 символа: буквы ASCII, цифры, `_`, `-`).
Содержимое задания описывается обычным Markdown перед блоком.
`reference` зарезервирован для старого эталона всего урока.

В админском редакторе на вкладке заданий доступны кнопки добавления SQL/Python.
При вводе директивы вручную идентификатор назначается при выходе из поля.
Для каждого блока есть отдельное поле эталона. После изменения языка необходимо
обновить эталон. При переименовании id эталон нужно заполнить для нового id;
автоматически переносить код между разными заданиями небезопасно.

## Хранение и API

Новая таблица и миграция **не нужны**. Используется `exercise_answers`:
ключ `(lesson_id, exercise_id)`, поле `answer` содержит JSON
`{"type":"code","language":"python","value":"...","execution":{...}}`.
При каждом сохранении эталоны запускаются в sandbox; `execution` содержит stdout,
stderr, exit_code, duration, признаки превышения лимитов и `success`.
Ошибки программы также фиксируются. Недоступность runner прерывает сохранение.
Старые тесты и общий эталон урока сохраняют свой формат.

* `GET /api/v1/admin/lessons/{lesson_id}/code-content` — Markdown,
  список `solutions` (`exercise_id`, `language`, `code`) и непрозрачная `version`.
* `PUT` по тому же адресу — полный Markdown, все эталоны кодовых блоков и
  версия, полученная при чтении. Для нового пустого урока допускается `null`.
* Существующий админский список ответов тоже возвращает эти записи.
  Поэлементная запись/удаление управляемых эталонов через старый API запрещены:
  используйте сохранение `code-content`.

Оба новых метода требуют `get_current_admin`, ответы запрещено кэшировать.
Сохранение проверяет дубликаты id среди тестов и кодовых блоков, язык,
непустые эталоны и точное соответствие наборов. Удалённые кодовые блоки
удаляют свои эталоны. При удалении урока действует существующий FK CASCADE.
Эталоны не передаются ученическому рендереру, в Markdown/MinIO не записываются,
исполняются отдельно при сохранении. Поля `solutions`, `answer`, `code` скрыты в логах ошибок.

Редактор использует серверное сохранение вместо presigned upload Markdown.
Старый API прямой загрузки остаётся для совместимости с уроками без кодовых
эталонов. При наличии таких эталонов выдача новой upload URL запрещена (409);
внешним админским клиентам нужно перейти на `code-content`. Ранее выданные
presigned URL действуют до истечения их срока, поэтому ими нельзя править
кодовые упражнения. Ученические API проверяют конфигурацию и не возвращают
эталоны даже при рассогласовании из-за сторонней записи в MinIO.

## Выполнение и проверка

Кнопка запуска использует существующий `/sandbox/execute`: изолированный
Python runner, профиль `light` по умолчанию. `SANDBOX_ASSIGNMENT_PROFILES`
позволяет переопределить профиль для `lesson_id:exercise_id`.
Ответ содержит вывод программы и `success`: код завершения 0 без превышения лимитов.
Попытка, результат и `is_correct` сохраняются в `LessonAttempt`. Только успешный
запуск с совпавшим результатом эталона засчитывается в прогрессе (`is_correct=true`).
Python: сравнение stdout (CRLF/LF и завершающие переводы строк нормализуются).
SQL: сравнение колонок и строк, включая порядок; используйте ORDER BY.
Без успешного сохранённого результата эталона запуск доступен, но `is_correct=null`.
Сравнения исходного кода с эталоном нет. Кнопка «Запустить и проверить» делает один запрос.

SQL выполняется в `analytics_training` под `sandbox_reader`: один SELECT с
явно указанными учебными таблицами. SQL-эталоны запускаются при сохранении так же,
как Python. Формат вывода SQL — JSON с колонками и строками в `stdout`.
`/check` используется для обычных тестов; кодовые ответы получают 422
`CODE_EXECUTION_REQUIRED`. Кодовые блоки учитываются при завершении урока.

## Конкурентные правки и ограничения хранилищ

Хеш версии включает Markdown и ответы; запись блокирует строку урока в PostgreSQL.
Устаревший редактор получает 409: скопируйте свои изменения и откройте урок заново.
Ошибка загрузки эталонов блокирует редактирование, а не заменяет их пустым списком.

MinIO и PostgreSQL не имеют общей транзакции. Сначала выполняется flush БД,
затем запись Markdown, затем commit. При ошибке commit прежний Markdown
восстанавливается. Аварийное завершение процесса между записями, неопределённый
результат сетевого запроса или ошибка самого восстановления всё ещё требуют
ручной проверки Markdown и записей `exercise_answers`. Это ограничение двух
хранилищ не устраняется без отдельного транзакционного протокола/миграции.
Метаданные урока и ответы старых тестов по-прежнему сохраняются отдельными запросами.

## Проверки без внешних сервисов

```sh
cd backend
venv/bin/python -m pytest tests/test_lesson_code_content.py tests/test_markdown_parser.py tests/test_student_exercises.py tests/test_exercise_check.py tests/test_lesson_completion.py -q
```

Во frontend: `npm test`, `npm run test:render`, `npm run lint`, `npm run build`.
Интеграционные тесты с реальными PostgreSQL/MinIO не требуются для unit-проверок;
запускать изменяющие БД тесты следует только на отдельной тестовой инфраструктуре.
