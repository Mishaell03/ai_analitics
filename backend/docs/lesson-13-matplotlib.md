# Урок 13: реальные данные и графики

Урок находится в `course-content/1/5/13.md`, опубликован в сиде курса 1 как первый урок модуля 5.
Три обязательных задания связаны с `exercise_answers` через стабильные ключи
`lesson_13_python_01`, `lesson_13_python_02`, `lesson_13_python_03`.
Числовой `answer_id` для связи с Markdown не используется.

Эталоны и ответы тестов: `infra/postgres/core_db/seeds/R__lesson_13_answers.sql`.
Режим заданий — `graded`. Успешное завершение Python само по себе не открывает
эталон: требуется PNG и корректные данные построенной диаграммы. Проверяются
тип (столбцы/линия), категории или месяцы, значения выручки, сортировка,
заголовок, обе подписи осей и нулевое начало числовой оси столбцов. Цвета и
горизонтальное/вертикальное расположение столбцов могут отличаться. Оценка
основана на выводе программы, а не на доказательстве того, как именно студент
выполнил вычисления; письменный аналитический вывод автоматически не оценивается.
Экспертный код не попадает в студенческий Markdown.

Старые записи урока 13 с `self_review` тоже проверяются по этим правилам без
сброса БД. Старые разрешения, полученные за `print("")`, больше не открывают
эксперта ни через страницу, ни через прямой API-запрос. Нужно пройти проверку
самого задания; незачтённый запуск возвращает объяснение в поле `feedback`.

## Проверка данных

Задание 3 содержит проекцию всех 36 строк `retail_order_items` из
`analytics_training/seeds/R__retail_sales.sql`. Проверяются точные ID, даты,
категории, количества, цены и статусы. Набор содержит 32 завершённые позиции,
62 проданные единицы и выручку 302780 руб. Бесплатная завершённая позиция — 28;
отменённые — 7, 17, 18, 29. Сводки заданий 1 и 2 сверяются с теми же строками.
Python не подключается к БД: весь учебный CSV включён в каждое решение.

## Как отображаются графики

Внутри изолированного Python-контейнера `plt.show()` сохраняет открытые фигуры
в PNG и передаёт ограниченные кадры через stdout. Runner выделяет их из текста,
проверяет PNG-заголовок, размеры и base64, возвращает отдельное поле `plots`.
В `chart_data` передаются ограниченные данные matplotlib-серий для проверки,
а не эталонные значения. Извлечение выполняется внутри того же student-контейнера.
API сохраняет этот контракт, а редактор отображает PNG после текстового вывода.
Не используются HTML/SVG, файловые пути хоста, Docker mounts или публичное
хранилище. Максимум 3 рисунка за запуск, 256 KiB каждый, до 2000×2000 пикселей.
PNG не сохраняются в историю попыток БД и доступны до перезагрузки страницы
или следующего запуска. `plt.show()` нужно вызывать явно.

Все три эталона выполнены локально через тот же wrapper, PNG действительно
создаются; график задания 3 проверен визуально. Проверены React-отрисовка PNG
и сборка фронта. Это не проверка развёрнутого приложения через браузер.

## Применение

1. Примените актуальные SQL-сиды и загрузите Markdown в MinIO обычным способом.
2. Перезапустите API и runner, чтобы загрузить новые контракты и wrapper.
   Для контейнерных сервисов обновите их образы. В sandbox-образе уже установлены
   pandas и matplotlib; wrapper передаётся runner при запуске программы.
3. Обновите сборку фронта. Эталоны урока 13 по умолчанию используют профиль
   `standard` (768 MiB / 15 сек.), не `light`.
4. Войдите учеником, откройте урок 13, выполните каждое решение. Под выводом
    должен появиться график, затем должна стать доступна кнопка решения эксперта.

Для контейнерного runner из `backend/`:

```bash
sudo docker compose -f docker-compose.yaml -f docker-compose.dev.yaml --profile sandbox up -d --build --no-deps sandbox_runner
```

Если API тоже контейнерный, обновите его отдельно:

```bash
sudo docker compose -f docker-compose.yaml -f docker-compose.dev.yaml --profile sandbox-api up -d --build --no-deps sandbox_api
```

Если API запущен через Python на хосте — перезапустите его процесс. Обновите
фронт (Vite dev перезагрузит исходники, для production нужна новая сборка) и
перезагрузите страницу. Сброс БД или `make fresh` для исправления не требуется.

Короткая проверка отображения (это не решение задания и не откроет эталон):

```python
import matplotlib.pyplot as plt
plt.plot([1, 2, 3], [2, 1, 4])
plt.show()
```

`print("")` не создаёт график. Если `plt.show()` выполнен, но изображения нет,
проверьте, что API вернул непустой `plots`, и что runner обновлён. Если PNG есть,
но нет `chart_data`, программа покажет график, но не сможет пройти проверку;
сообщение объяснит необходимость обновления runner.

## Автотесты

```bash
venv/bin/python -m pytest tests/test_lesson_13_plots.py -q
```

Для локального теста нужны pandas и matplotlib в venv. Тесты сверяют CSV с
SQL-сидом, месячные и категориальные суммы, ключи тестов и эталонов, получают
PNG из всех трёх программ, проверяют ограничения и отказ для не-PNG данных.
Контейнерная проверка `test_matplotlib_show_returns_png_to_api_client` находится
в `tests/test_sandbox_docker.py` и запускается только явно с
`SANDBOX_DOCKER_TESTS=1` на подготовленной, простаивающей песочнице.

Для проверки React-отрисовки из каталога `front`:

```bash
npx vite build --ssr tests/plots.render.jsx --outDir tests/.ssr-plots --logLevel warn
node tests/.ssr-plots/plots.render.js
```
