# Логи админки

Раздел фронта: `/admin/logs`. Две отдельные вкладки: системные логи и AI-логи.
API использует существующую сессионную авторизацию и `get_current_admin`.
Ответы помечены `Cache-Control: no-store`.

## Обновление

Перед запуском новой версии бэкенда примените миграцию V11:

```bash
cd backend
make logs-migrate
```

Команда использует тот же набор Flyway locations, что и `make ai-migrate`,
но обновляет core_db до V11. Существующие записи не удаляются.
Миграция добавляет `backend_error_logs.error_code` и индексы для списков.
У старых ошибок поле кода останется пустым; коды событий уже сохранены в `event`.

## Системные логи

`GET /api/v1/admin/logs`

Объединяет `users_event_logs` и `backend_error_logs`. Одна ошибка может иметь
две записи: бизнес-событие и техническую ошибку. Они различаются источником.

- `source`: `event` / `backend`;
- `status`: `success` (2xx), `redirect` (3xx), `client_error` (4xx), `server_error` (5xx);
- `status_code`: точный HTTP-код, например `403`;
- `code`: точный код события/ошибки, вводится администратором вручную;
- `session_id`: ID сессии, не токен;
- `user`: поиск по части имени/email или точному числовому ID;
- `user_id`: точный ID пользователя.

Технический лог связывается с пользователем через сессию. Если сессия удалена
или запрос был анонимным, пользователь может отсутствовать.
Выдача намеренно не содержит тела запроса и сырого сообщения исключения:
в них могут присутствовать секреты или параметры SQL.

## AI-логи

`GET /api/v1/admin/logs/ai`

Использует уже сохраняемую историю вопросов и ответов наставника, без
дублирования текста в системных логах. В выдаче есть пользователь, вопрос,
ответ, урок, модель, статус и код ошибки. Вопросы без ответа также видны.

Фильтры: `user`, `user_id`, `status` (`pending`, `completed`, `refused`, `failed`).
Внутренние промпты, память диалога, provider_response и context_snapshot не выдаются.
Логируются обращения, сохранённые сервисом наставника; отклонённые до сохранения
вопроса запросы видны только как системные события/ошибки.

## Общие фильтры

- `date_from` и `date_to`: календарные даты `YYYY-MM-DD`, обе включительно, UTC;
- `page`: от 1;
- `page_size`: 1–100, по умолчанию 20.

Все заданные фильтры применяются одновременно на сервере. Сортировка — новые
записи первыми с дополнительным ключом для совпадающих времён.
Ответ: `page`, `page_size`, `total`, `total_pages`, `items`.
Вкладки сбрасывают фильтры при переключении; кнопка «Применить» очищает текущую
консоль и загружает первую страницу. Фронт запрашивает по 50 записей и автоматически
добавляет следующие страницы при прокрутке внутри консоли. Повторяющиеся записи
между страницами не дублируются. Фильтры находятся в сворачиваемой панели.
