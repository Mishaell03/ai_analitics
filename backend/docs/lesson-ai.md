# AI-наставник: DeepSeek API и боковой чат урока

## Быстрая настройка

Для backend, работающего на хосте на порту 8000, достаточно добавить в
`backend/app/.env`:

```dotenv
DEEPSEEK_API_KEY=ваш_ключ_DeepSeek
MODEL="deepseek-flash"
MAX_TOKENS=1024
THINKING="disabled"
```

Ключ обязателен. Остальные значения по умолчанию: `MODEL=deepseek-flash`,
`MAX_TOKENS=1024`, `THINKING=disabled`. В `backend/app/.env` также допустима запись
с пробелами: `MODEL = "deepseek-flash"`. Значение `THINKING` — `disabled` или `enabled`.
Поддерживается **одна модель**, не список. Доступные модели/цены проверьте в
DeepSeek Platform. На дату реализации актуальные имена — `deepseek-flash` и
`deepseek-v4-pro`. Пул моделей, автоматическое переключение и скрытые retries удалены.

**API платный**, требуется доступный баланс аккаунта. Бесплатный веб-чат DeepSeek
не предоставляет приложению бесплатный API. Баланс не пополняется автоматически.

Полные одинаковые AI-настройки приведены и в `backend/.env.example`, и в
`backend/app/.env.example`:

```dotenv
DEEPSEEK_API_KEY=
MODEL="deepseek-flash"
MAX_TOKENS=1024
THINKING="disabled"
DEEPSEEK_USER_DAILY_LIMIT=50
DEEPSEEK_USER_MINUTE_LIMIT=5
DEEPSEEK_PROJECT_DAILY_LIMIT=200
DEEPSEEK_PROJECT_MINUTE_LIMIT=10
DEEPSEEK_MAX_INPUT_BYTES=18000
```

Все параметры кроме ключа имеют эти значения по умолчанию. Настройки Google AI
удалены из обоих локальных `.env` и примеров. Старые `DEEPSEEK_MODEL` и
`DEEPSEEK_MAX_OUTPUT_TOKENS` больше не читаются. Не копируйте
пример поверх своего файла с настройками БД/хранилища.

LLMSettings читает переменные процесса, затем `backend/app/.env`, затем `backend/.env`.
Учтите существующий общий конфиг `app/core/config.py`: при старте приложения он
загружает `backend/app/.env` с `override=True`. Не задавайте конфликтующие значения
в нескольких местах. Для Compose API ключ задаётся в `backend/.env`, а не внутри
`backend/app/.env` (файл с секретами не копируется в образ).

После изменения конфигурации/кода перезапустите backend самостоятельно. Если
используется контейнерный API, пересоберите его образ самостоятельно. Промпт
`backend/infra/llm/mentor.md` кэшируется процессом и копируется в образ при сборке.

## Проверка сессий DeepSeek

Официальный Chat Completions API **stateless**: DeepSeek не хранит доступную через
session id историю диалога. В Responses API также прямо указано, что
`previous_response_id`, `conversation` и `store` не поддерживаются.

Поэтому сессии реализованы **на backend в PostgreSQL**, а не в API провайдера:

- У каждого пользователя один отдельный диалог для каждого урока: уникальная пара
  `(user_id, lesson_id)` в `ai_conversations`.
- Новый урок начинает пустой диалог: сообщения и сводка другого урока не переносятся.
- Возврат в уже открывавшийся урок восстанавливает его собственную историю.
  Обновление страницы, повторный вход и перезапуск backend не стирают её.
- Полная история вопросов/ответов остаётся в БД, но **не отправляется целиком**.
- В чате и HTTP-истории видны только **последние 10 запросов текущего урока**.
  Записи старше этого окна сохраняются лишь как внутренний аудит, для квот и
  идемпотентности. Они не удаляются и не доступны через пагинацию чата.
- Общий краткий контекст из `infra/llm/brief_context.md` (до 1000 символов)
  передаётся **на каждом уроке и при каждом запросе**. Отредактируйте этот файл
  под общие особенности обучения; после изменения перезапустите backend.
  Общий контекст не содержит личной переписки. Память ученика между уроками
  не переносится.
- В каждом запросе отправляются короткие метаданные курса/урока, фрагменты урока
  до 2400 символов, сводка до 1000 символов, до **10 последних успешных пар**
  вопрос/ответ текущего урока (200/350 символов на пару), общий краткий контекст,
  новый вопрос и контекст ученика.
- Фрагменты выбираются локально по словам вопроса: введение и релевантные части,
  а не всегда первые строки большого урока. Вызовов embedding API нет.
- При превышении byte-бюджета сокращаются текст урока/сводка/описание, затем
  удаляются самые старые пары из передаваемой истории, поэтому в отдельных
  запросах их может быть меньше 10. Сам вопрос, общий контекст и контекст
  пользователя не обрезаются.
- Сводка обновляется в том же JSON-ответе модели — отдельного платного запроса
  для суммаризации нет. Ошибки и отказы не обновляют учебную память.
- При изменении урока, системного промпта или выбранной модели память для запроса
  начинается заново; старая история остаётся видна пользователю. Старая память
  Google не включается в DeepSeek-контекст.

`provider_state` — историческое имя существующей JSONB-колонки. Теперь она хранит
только локальные `provider=deepseek` и fingerprint контекста, **не remote session id**.
Исторические SQL-миграции не переписывались, прикладные данные не удаляются.

Контекст не растёт с длиной диалога. Тем не менее передаваемые токены учитываются
DeepSeek при оплате; автоматический context cache провайдера не является обещанием
бесплатной памяти и не используется вместо локальных ограничений.

## Транспорт и безопасность

- Фиксированный endpoint: `https://api.deepseek.com/chat/completions`.
- Прямой HTTPS, авторизация только серверным `Authorization: Bearer …`.
- Прокси и зависимость от Xray удалены. `trust_env=False`: `HTTP_PROXY`,
  `HTTPS_PROXY`, `ALL_PROXY` не перенаправляют AI-запросы. Редиректы выключены.
- Compose API получает обычную сеть `api_egress_net` для исходящего HTTPS.
  Внутренние сети БД и sandbox остаются отдельными.
- Один запрос — максимум одна HTTP-попытка к одной модели, без автоматических
  повторов после 429/5xx/timeout и без переключения на другую модель.
- `THINKING=disabled` отключает thinking; лимит ответа `MAX_TOKENS=1024` по умолчанию.
- JSON Output (`response_format=json_object`), пример JSON в системной инструкции
  и строгая Pydantic-проверка `decision`, `answer`, `summary`.
- Не подключены tools, поиск, function calling, выполнение кода, загрузка файлов
  или URLs. Неожиданные tool calls, HTML/ссылки и незавершённые ответы отвергаются.
- `reasoning_content` не показывается ученику и не попадает в память. Ответ до
  3000 символов выводится обычным React-текстом без HTML-интерпретации.
- Таймаут запроса 45 секунд, HTTP read timeout 40 секунд, connect 5 секунд;
  lease диалога 90 секунд. Размер ответа провайдера ограничен 64 KiB.
- Размер нового input вместе с системными инструкциями ограничен 18000 UTF-8
  байт по умолчанию. Это byte-бюджет, не точный счётчик токенов.
- Квоты вопросов пользователя и проекта общие для всех workers через PostgreSQL.
  Они не заменяют денежный бюджет DeepSeek; контролируйте баланс в кабинете.
- В контекст не включаются cookie-сессии, серверные секреты, чужие диалоги и эталоны
  решений. Не отправляйте персональные данные/секреты в самих вопросах.
- Ответы/контекст/usage сохраняются в БД для аудита. Доступ к БД и резервным копиям
  должен быть ограничен; для production нужен собственный срок хранения данных.
- В общий лог пишутся только question id, модель и безопасный код ошибки — без
  вопроса, ключей и исходного текста ошибки провайдера.

Семантическую устойчивость модели к prompt injection гарантировать невозможно.
Ответ модели не считается разрешением или исполняемой командой.

## Боковая панель

На широком экране наставник находится **справа от содержимого урока** и остаётся
видимым при прокрутке. На экранах до 1050px кнопка открывает боковую выдвижную
панель справа, а не чат внизу урока. Используется native modal dialog с фокусом
внутри, закрытием по Escape и кнопкой закрытия. При смене урока компонент
пересоздаётся и загружает историю именно нового урока.

## HTTP API и ошибки

Адрес остаётся прежним:

`/api/v1/courses/{course_slug}/modules/{module_id}/lessons/{lesson_id}/ai/messages`

Требуются cookie-сессия, опубликованный курс/модуль/урок, запись на курс и
существующая CSRF origin-проверка. Запрос не может выбирать чужого пользователя,
модель, системный промпт, API URL или собственную историю.

POST:

```json
{"request_id":"35838293-82dc-4c3d-8fb5-a670c6ed4b13","question":"Как работает GROUP BY?","user_context":"Я новичок"}
```

Вопрос до 2000 символов, user_context до 1000, тело до 24 KiB. UUID создаёт клиент.
Повтор того же UUID с тем же телом возвращает сохранённый результат **без нового
API-вызова/локального списания квоты**. Другой текст с тем же UUID — 409.
Вопрос сохраняется до внешнего вызова; ответ — до возврата клиенту.

HTTP 200 означает сохранённый результат, а не обязательно успешный AI-ответ:
смотрите `status` (`completed`, `pending`, `refused`, `failed`). В ответ также
добавлено безопасное поле `error_code`, ключи и сырой provider response не выдаются.

Основные коды:

| Код | Причина |
|---|---|
| `AI_NOT_CONFIGURED` | не указан ключ или некорректна серверная конфигурация |
| `AI_AUTH_FAILED` | DeepSeek вернул 401, проверьте ключ |
| `AI_BALANCE_REQUIRED` | DeepSeek вернул 402, недостаточно средств |
| `AI_PROVIDER_FORBIDDEN` | DeepSeek запретил доступ, 403 |
| `AI_MODEL_UNAVAILABLE` | выбранная модель недоступна, 404 |
| `AI_RATE_LIMITED` | лимит DeepSeek, 429 |
| `AI_PROVIDER_UNAVAILABLE` | сеть/timeout/5xx/неожиданный HTTP-статус |
| `AI_PROVIDER_BAD_REQUEST` | DeepSeek отклонил параметры, 400 |
| `AI_INPUT_TOO_LARGE` | даже после сокращения превышен byte-бюджет |
| `AI_OUTPUT_TRUNCATED` | ответ превысил output token limit |
| `AI_RESPONSE_REJECTED` | неподходящий/пустой JSON или небезопасный формат |

Ошибки ключа/баланса/модели теперь отображаются понятным текстом в чате.
Для pending запроса есть «Проверить запрос», повторяющее тот же UUID. После аварии
повтор pending UUID по истечении lease фиксирует `failed`, а не дублирует платный
запрос. При сетевом обрыве внешняя система уже могла обработать запрос — абсолютная
exactly-once гарантия между PostgreSQL и внешним API невозможна.

GET `?after_id=0&limit=10`: `{"messages":[],"next_after_id":null}`. Максимум 10 запросов
текущего урока, от старых к новым внутри этого окна. Пагинация при меньшем `limit`
работает только в пределах последних 10 запросов. GET не вызывает DeepSeek.
`Cache-Control: no-store, private`.

## Применение и проверки

**Контейнеры не запускались/не перезапускались, миграции не применялись.**

1. Добавьте `DEEPSEEK_API_KEY` в свой `.env`; старые Google/proxy-настройки удалите.
2. Если V9 и V10 уже применены, **новая миграция для перехода не нужна**.
   Для новой БД примените `make ai-migrate` из `backend/` самостоятельно
   после резервного копирования/проверки плана Flyway. Target остаётся 10.
3. Перезапустите host-backend самостоятельно. Для контейнерного backend нужна
   пересборка API и применение обновлённого Compose, чтобы появилась прямая egress-сеть.
4. Обновите frontend через свой Vite dev server или production build.
5. Сервис Xray удалён из Compose, но **уже работающий контейнер не остановлен**.
   Его остановку/удаление, если он больше нигде не нужен, выполняете вы вручную.

Offline-тесты, без сети и изменения прикладной БД:

```sh
venv/bin/python -m pytest tests/test_ai.py tests/test_ai_sessions.py -q
```

Опциональные PostgreSQL-тесты создают/удаляют временную схему и выполняют внутри
неё исторические V9/V10. Агент их не запускал:

```sh
AI_POSTGRES_TESTS=1 venv/bin/python -m pytest tests/test_ai_postgres.py -q
```

Реальный DeepSeek-запрос не выполнялся: он требует вашего API-ключа и может
расходовать баланс. После настройки задайте два вопроса, обновите страницу,
затем откройте другой урок: прежняя история должна сохраниться только в своём уроке.
