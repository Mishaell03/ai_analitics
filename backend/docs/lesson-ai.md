# AI-наставник урока (Gemini + Xray)

## Запуск

В `backend/.env`:

```dotenv
GEMINI_API_KEY=ключ_из_Google_AI_Studio
GEMINI_PROXY_URL=http://127.0.0.1:10810
GEMINI_MODELS=gemini-3.5-flash-lite,gemini-3.1-flash-lite
GEMINI_USER_DAILY_LIMIT=50
GEMINI_USER_MINUTE_LIMIT=5
```

Host-запуск также поддерживает `backend/app/.env` (приоритет над `backend/.env`),
как существующий конфиг приложения. Переменные процесса имеют приоритет в LLMSettings.
Для Compose ключ и список моделей задавайте в `backend/.env`. Пустое значение прокси
считается ошибкой, а не разрешением прямого подключения. API key не передаётся
клиенту и не сохраняется в истории. Поддерживаемая конфигурация по умолчанию —
Flash-Lite с минимальным thinking и ограниченным ответом.

`GEMINI_MODELS` — от 1 до 5 моделей через запятую в порядке приоритета.
Повторяющиеся имена исключаются. При **HTTP 429** от первой модели используется
следующая. Если квоты исчерпаны у всех — сохраняется `failed` с внутренним кодом
`AI_MODELS_QUOTA_EXCEEDED`. Ошибки прокси, авторизации, 5xx и safety-отказы не
вызывают переключение. Общий deadline 35 секунд действует на весь список.
Все попытки остаются через Xray; использованная модель сохраняется в вопросе,
список попыток и HTTP-статусы — в аудите ответа. Старый `GEMINI_MODEL` поддерживается,
если `GEMINI_MODELS` отсутствует. В Compose также используйте `GEMINI_MODELS`.

Google может вернуть 403 с сообщением, что бесплатный тариф недоступен для
проекта и требуется billing. Это сохраняется как `AI_BILLING_REQUIRED` в аудите.
Нужно настроить доступ к Gemini в самом Google-проекте или использовать ключ
другого доступного проекта. Переключение модели при таком отказе не выполняется.

Из `backend/` применить миграцию существующим Flyway:

```sh
make ai-migrate
```

Это миграция `V9__lesson_ai.sql` только в `core_db`, без reset.
Flyway видит оба каталога — `migrations` и `seeds`, поскольку уже применённые
repeatable-миграции должны участвовать в валидации. Неизменённые seed-файлы повторно
не выполняются; при изменении их checksum действует стандартное поведение Flyway.
Нужен доступ к Docker (при необходимости `sudo make ai-migrate`).
Если приложение запущено без autoreload, перезапустить backend.

В Compose API использует `http://xray:10810` и уже подключён к `ai_backend_net`.
`app/Dockerfile` копирует `infra/llm/context.md` в образ; после изменения файла
контейнерный API нужно пересобрать. Host API читает этот же файл из репозитория.
Текст кэшируется в процессе, поэтому после правки нужен перезапуск API.

Проверка сети выполняется только через явно заданный прокси. `trust_env=False`,
редиректы выключены, прямого fallback нет. Только HTTP 429 разрешает попытку
следующей модели из серверного списка, без повторения уже использованной модели.
Google URL фиксирован в коде; модель и proxy задаются только администратором.
Xray `ai-http` использует отдельный `gemini-pool` с существующими выходами
`proxy-ai-*` (NL/GB), `fallbackTag=block`. Общий пул socks/http не используется
для Gemini: случайная страна выхода может вызвать отказ Google по региону.
После изменения `infra/xray/config.json` перезапустить Xray:
`docker compose restart xray`. Поддержка региона зависит также от геолокации
конкретного IP выхода у Google; название прокси не гарантирует доступность API.

## HTTP API

Базовый адрес:
`/api/v1/courses/{course_slug}/modules/{module_id}/lessons/{lesson_id}/ai/messages`

Требуется существующая cookie-сессия, опубликованный курс/модуль/урок и запись
пользователя на курс. Принадлежность урока и модуля проверяется сервером.
Запросы браузера проходят существующую CSRF-проверку.

### POST — вопрос

```json
{
  "request_id": "35838293-82dc-4c3d-8fb5-a670c6ed4b13",
  "question": "Почему после GROUP BY нельзя выбрать произвольный столбец?",
  "user_context": "Я новичок. Понимаю SELECT и WHERE, но путаюсь с группировкой."
}
```

`request_id` — UUID, например `crypto.randomUUID()` в браузере. При повторной
отправке того же вопроса после сетевой ошибки используйте тот же UUID: сервер
вернёт сохранённое состояние и не вызовет Gemini повторно. UUID нельзя повторно
использовать для другого текста (409). Новый осознанный запрос — новый UUID.

Лимиты: вопрос 2000 символов, краткий пользовательский контекст 1000 символов,
тело запроса 24 KiB. Клиент не может задавать пользователя, system prompt, модель,
полную историю, разрешения на просмотр решений, API URL или proxy.

Ответ (HTTP 200, `Cache-Control: no-store, private`):

```json
{
  "question_id": 12,
  "request_id": "35838293-82dc-4c3d-8fb5-a670c6ed4b13",
  "question": "Почему после GROUP BY нельзя выбрать произвольный столбец?",
  "user_context": "Я новичок. Понимаю SELECT и WHERE, но путаюсь с группировкой.",
  "answer": "GROUP BY объединяет строки в группы…",
  "status": "completed",
  "created_at": "2026-10-28T12:00:00Z"
}
```

Статусы: `completed` (проверенный формат учебного ответа), `refused` (отказ по
политике/неприемлемый ответ), `failed` (модель/прокси недоступны), `pending`
(повтор пришёл во время обработки; answer=null).

Вопрос фиксируется **до** обращения к модели. Ошибки провайдера тоже сохраняются:
HTTP 200 означает, что запись вопроса обработана, а результат определяет `status`.
Внутренние ошибки/сырой ответ/ключи в публичный ответ не входят.
Без настроенного ключа вопрос получает `failed`, без сетевого вызова.

409 `AI_REQUEST_IN_PROGRESS` — другой вопрос в том же диалоге ещё выполняется
(или другой процесс принимает запрос пользователя).
429 `AI_QUOTA_EXCEEDED` — общая квота пользователя по всем урокам.
Повтор с тем же UUID не расходует квоту.

### GET — личная история урока

`GET .../ai/messages?after_id=0&limit=30`

```json
{"messages": [], "next_after_id": null}
```

Сортировка от старых к новым. Для следующей страницы передать `next_after_id`
в `after_id`. Максимум 50 записей за страницу. Пользователь определяется только
по сессии; чужие диалоги и другие уроки в выборку не попадают.

Отображать `answer` как текст или через существующий безопасный Markdown-рендерер.
Нельзя использовать `innerHTML`, выполнять код из ответа или автоматически
передавать ответ в sandbox. UI чата в рамках этого backend API не добавляется.

## Таблицы и память

- `ai_conversations`: одна запись на `(user_id, lesson_id)`, краткая сводка,
  время обновления и lease активного запроса.
- `ai_questions`: UUID запроса, текст вопроса и пользовательский контекст,
  снимок переданного контекста, hash системного промпта, модель и статус.
- `ai_answers`: отдельная запись ответа, исходный ответ Google для внутреннего
  аудита, безопасный публичный текст, код ошибки, счётчики токенов.

FK связывают историю с пользователем и уроком. Удаление пользователя/урока
каскадно удаляет связанные диалоги, вопросы и ответы. Сырые ответы провайдера и
context_snapshot доступны только прямому доверенному доступу к БД.

В модель передаются:
1. Полный текст `infra/llm/context.md` как systemInstruction плюс контракт ответа.
2. Название/описание курса, модуль, название и первые 6000 символов публичного урока.
3. Сводка предыдущего диалога до 1000 символов.
4. До трёх последних успешных пар вопрос/ответ (1000/1500 символов на пару).
5. Новый вопрос и краткий контекст пользователя.

Сводка обновляется в том же ответе Gemini, отдельного платного вызова для памяти
нет. Отказы и ошибки не попадают в память. Полная история остаётся в БД, но не
отправляется каждый раз. В ответе максимум 1536 output tokens; публичный текст
до 3000 символов. Вопросы ограничены 5/минуту и 50/24 часа по умолчанию.
Квоты и идемпотентность обеспечиваются PostgreSQL, в том числе при нескольких workers.

На время HTTP-вызова транзакция БД не удерживается. Для одного диалога действует
lease 90 секунд при общем deadline Gemini 35 секунд. При аварии повтор того же
UUID после истечения lease фиксирует `failed` без повторной оплаты; следующий
новый вопрос может продолжить диалог. Автоматического фонового retry нет.

## Границы безопасности

Gemini получает только текст. Tool definitions, function calling, code execution,
поиск, загрузка URL и доступ к прикладной БД не подключены. Возвращённые моделью
команды не исполняются; functionCall и executableCode в ответе отклоняются.
Эталоны из `exercise_answers`, чужая история, данные сессии и серверные секреты
не включаются в запрос. История, сводка, код ученика и текст урока всегда являются
данными, а не system-инструкциями или разрешением на выдачу эталонов.

Включены Gemini safety filters, структурированный ответ с решением answer/refuse,
проверка завершённости, размера и формата ответа. HTML, изображения и ссылки
не допускаются. При отказе показывается локальный нейтральный текст, а исходный
ответ остаётся только в аудите. Вопросы/ответы не дублируются в общих error-логах.

Отсутствие инструментов технически исключает выполнение действий моделью в проекте.
Семантическое соблюдение темы и устойчивость к prompt injection не имеют абсолютной
гарантии у генеративной модели: системный промпт, классификация, фильтры и аудит
снижают риск, но не превращают сгенерированный текст в доверенную команду.

## Проверки

```sh
venv/bin/python -m pytest tests/test_ai.py -q
AI_POSTGRES_TESTS=1 venv/bin/python -m pytest tests/test_ai_postgres.py -q
```

Второй набор создаёт временную схему `test_ai_*` в настроенном PostgreSQL и удаляет
её после проверки. Прикладная `public` не изменяется, Gemini заменён mock-клиентом:
тесты не расходуют API-квоту. Нужны права CREATE SCHEMA для тестового подключения.
