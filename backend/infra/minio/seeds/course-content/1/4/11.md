## 1. От pandas к SQL

### 1.1. Зачем нужен ещё один инструмент?

В pandas мы работали с таблицами примерно так:

```python
df = pd.read_csv(StringIO(csv_text))
```

Затем выбирали строки, рассчитывали показатели и получали результаты.

Но в реальных компаниях данные часто хранятся не в отдельных CSV-файлах, а в **базах данных**.

Например, интернет-магазин постоянно получает информацию о покупателях, заказах, товарах и платежах.

Хранить и обрабатывать такую информацию помогает система управления базами данных.

### 1.2. Что такое PostgreSQL и SQL?

**Реляционная база данных** хранит информацию в таблицах, между которыми могут существовать связи.

В таблицах используются уже знакомые вам понятия:

- Строки — отдельные записи.
- Столбцы — характеристики записей.
- Типы данных — числа, текст, даты и другие значения.
- Идентификаторы — значения, позволяющие различать записи.

**PostgreSQL** — система управления реляционными базами данных.

**SQL** (*Structured Query Language*) — язык, с помощью которого можно запрашивать и обрабатывать данные в таких системах.

Сравним знакомые инструменты:

| Инструмент | Для чего используется |
|---|---|
| CSV | Представление табличных данных в текстовом формате |
| pandas | Обработка и исследование таблиц в Python |
| PostgreSQL | Хранение и управление данными в реляционной базе |
| SQL | Запрос информации из реляционной базы |

SQL и PostgreSQL — не одно и то же. PostgreSQL выполняет SQL-запросы, обращаясь к хранящимся в базе данным.

### 1.3. Где будем выполнять запросы?

На образовательной платформе есть встроенное поле выполнения SQL.

Запросы выполняются в **отдельной учебной базе PostgreSQL**, а не в базе, где хранятся данные пользователей и самой образовательной платформы.

В этом уроке используются только запросы для чтения информации.

Вы будете работать с учебной таблицей:

`order_items`

Она должна быть заранее подготовлена преподавателем или администратором. Если при выполнении запроса появляется сообщение о том, что таблица не существует, сообщите об этом преподавателю: создавать таблицы самостоятельно не требуется.

В учебном SQL-редакторе вы будете:

1. Самостоятельно писать запрос в пустом поле.
2. Запускать его.
3. Изучать результат или текст ошибки PostgreSQL.
4. При необходимости исправлять собственный запрос и выполнять его повторно.

После выполнения задания можно дополнительно посмотреть эталонное решение преподавателя.

Автоматической оценки правильности запросов здесь нет: важно самостоятельно сопоставлять результат с условием задачи.

### 1.4. Знакомая таблица `order_items`

В «Северном свете» одна строка `order_items` означает **одну товарную позицию заказа**.

Таблица содержит девять столбцов:

| Столбец | Значение |
|---|---|
| `line_item_id` | Уникальный идентификатор товарной позиции |
| `order_id` | Идентификатор заказа |
| `order_date` | Дата заказа |
| `customer_id` | Идентификатор покупателя |
| `product` | Наименование товара |
| `category` | Категория товара |
| `quantity` | Количество |
| `unit_price` | Цена одной единицы |
| `status` | Статус |

Например, четыре строки исходного набора выглядят так:

| line_item_id | order_id | product | quantity | unit_price | status |
|---|---|---|---:|---:|---|
| 2004 | 5003 | Bottle | 2 | 900 | completed |
| 2005 | 5004 | Notebook | 5 | 180 | completed |
| 2006 | 5005 | Bottle | 1 | 900 | cancelled |
| 2007 | 5006 | Mug | 1 | 450 | completed |

В полном учебном наборе десять товарных позиций.

Как и раньше:

- `line_item_id` должен быть уникальным.
- `order_id` может повторяться.
- Количество положительно, цена неотрицательна.
- Для учебной выручки учитываются только позиции `completed`.
- Выручка позиции равна количеству, умноженному на цену.

## 2. Первые SQL-запросы

### 2.1. Получаем данные с помощью `SELECT`

Начнём с простого запроса:

```sql
SELECT *
FROM order_items;
```

Разберём его:

- `SELECT` — указывает, какую информацию нужно получить.
- `*` — означает «все столбцы».
- `FROM` — указывает таблицу-источник.
- `order_items` — название таблицы.
- `;` — обозначает конец SQL-инструкции.

Если учебная таблица подготовлена правильно, запрос вернёт десять записей со всеми девятью столбцами.

SQL-запрос — не команда Python. Он выполняется системой PostgreSQL.

В SQL принято записывать ключевые слова заглавными буквами: `SELECT`, `FROM`, `WHERE`.

Для этих ключевых слов регистр обычно не влияет на выполнение, но заглавные буквы делают запрос более читаемым.

### 2.2. Выбираем только нужные столбцы

Не всегда необходимо выводить всю таблицу.

Например, если мы хотим узнать названия товаров и их количества:

```sql
SELECT line_item_id, product, quantity
FROM order_items;
```

Здесь после `SELECT` перечислены три столбца.

Результат содержит значения только этих полей.

Это похоже на выбор столбцов в pandas:

`df[["line_item_id", "product", "quantity"]]`

**Совет:** в аналитической работе полезно запрашивать именно те столбцы, которые нужны для решения задачи.

### 2.3. Фильтруем строки с помощью `WHERE`

Руководитель хочет увидеть только завершённые товарные позиции.

Для этого используется `WHERE` — условие отбора строк.

```sql
SELECT line_item_id, product, status
FROM order_items
WHERE status = 'completed';
```

Разберём:

- `WHERE` задаёт условие.
- `status = 'completed'` проверяет значение статуса.
- В результат попадают только строки, удовлетворяющие условию.

**Обратите внимание на важное различие:**

В Python сравнение на равенство записывается через `==`.

В SQL используется один знак:

```sql
status = 'completed'
```

Текстовые значения SQL обычно заключаются в **одинарные кавычки**.

При выполнении этого запроса по исходному набору выбираются девять завершённых позиций. Отменённая позиция 2006 не входит в результат.

### 2.4. Числовые сравнения

В SQL можно применять привычные операторы сравнения.

| Оператор SQL | Значение |
|---|---|
| `=` | Равно |
| `<>` | Не равно |
| `>` | Больше |
| `<` | Меньше |
| `>=` | Больше или равно |
| `<=` | Меньше или равно |

Например:

```sql
SELECT line_item_id, product, unit_price
FROM order_items
WHERE unit_price >= 900;
```

Запрос выбирает позиции, у которых цена одной единицы составляет **не менее 900 рублей**.

Обратите внимание: условие касается цены, но **не проверяет статус**.

Поэтому в результат может попасть отменённая позиция.

Это не техническая ошибка. SQL выполнил именно тот запрос, который мы написали.

### 2.5. Объединяем условия через `AND`

Допустим, нам нужны позиции, которые одновременно:

- Завершены.
- Содержат не менее двух единиц товара.

```sql
SELECT line_item_id, product, quantity
FROM order_items
WHERE status = 'completed'
  AND quantity >= 2;
```

`AND` означает логическое «И».

Оба условия должны быть истинными для каждой выбранной строки.

Сравните с pandas, где вы использовали `&` между логическими масками.

SQL записывает логическое «И» словом `AND`.

### 2.6. Оператор `OR` и круглые скобки

`OR` означает логическое «ИЛИ». Достаточно выполнения хотя бы одного условия.

Например:

```sql
SELECT line_item_id, product, unit_price, status
FROM order_items
WHERE status = 'cancelled'
   OR unit_price >= 2400;
```

Этот запрос выбирает позиции, которые либо отменены, либо имеют цену от 2400 рублей за единицу.

Иногда требуется совместить `AND` и `OR`.

Например, показать только завершённые позиции из категорий `Home` или `Accessories`:

```sql
SELECT line_item_id, category, status
FROM order_items
WHERE status = 'completed'
  AND (
      category = 'Home'
      OR category = 'Accessories'
  );
```

Круглые скобки объединяют два возможных значения категории.

В SQL `AND` имеет более высокий приоритет, чем `OR`. Без скобок условие может приобрести другой смысл.

Например, запись

`status = 'completed' AND category = 'Home' OR category = 'Accessories'`

может включить отменённые позиции категории `Accessories`, потому что условие категории в правой части `OR` будет достаточно выполнить само по себе.

**Главное:** сначала сформулируйте правило обычными словами, а затем запишите SQL-условие, сохраняя его смысл.

## 3. Сортировка и ограничение результата

### 3.1. `ORDER BY` — сортировка

Если выполнить запрос без `ORDER BY`, PostgreSQL **не гарантирует определённый порядок строк**.

Чтобы получить результат в нужном порядке, используется сортировка.

```sql
SELECT line_item_id, product, unit_price
FROM order_items
WHERE status = 'completed'
ORDER BY unit_price DESC;
```

Здесь:

- `ORDER BY unit_price` — сортировка по цене единицы товара.
- `DESC` — по убыванию, от большей цены к меньшей.
- `ASC` — по возрастанию.

Если несколько позиций имеют одинаковую цену, одного условия сортировки недостаточно, чтобы гарантировать их взаимный порядок.

Добавим второе:

```sql
SELECT line_item_id, product, unit_price
FROM order_items
WHERE status = 'completed'
ORDER BY unit_price DESC, line_item_id ASC;
```

Теперь позиции сначала сортируются по цене в порядке убывания, а при одинаковой цене — по `line_item_id` в порядке возрастания.

Так результат становится однозначным.

### 3.2. `LIMIT` — ограничение числа строк

Предположим, мы хотим увидеть только две самые дешёвые завершённые позиции.

```sql
SELECT line_item_id, product, unit_price
FROM order_items
WHERE status = 'completed'
ORDER BY unit_price ASC, line_item_id ASC
LIMIT 2;
```

Результат:

| line_item_id | product | unit_price |
|---|---|---:|
| 2002 | Notebook | 180 |
| 2005 | Notebook | 180 |

`LIMIT 2` означает, что запрос вернёт не больше двух строк.

Но важно понимать разницу:

- `WHERE` решает, **какие строки подходят**.
- `ORDER BY` устанавливает их **порядок**.
- `LIMIT` определяет, **сколько строк показать**.

Чтобы получить именно две самые дешёвые позиции, сортировка должна быть выполнена перед ограничением.

Без подходящего `ORDER BY` команда `LIMIT 2` не гарантирует выбор самых дешёвых товаров.

## 4. Считаем показатели в SQL

Ранее в pandas мы использовали `len()`, `nunique()` и `.sum()`.

В SQL существуют похожие возможности.

### 4.1. `COUNT(*)` — количество строк

```sql
SELECT COUNT(*)
FROM order_items;
```

Запрос считает строки таблицы.

Для нашего полного учебного набора результат — **10 товарных позиций**.

Если требуется посчитать только завершённые:

```sql
SELECT COUNT(*)
FROM order_items
WHERE status = 'completed';
```

Здесь `WHERE` сначала ограничивает рассматриваемые строки, а `COUNT(*)` подсчитывает их количество.

### 4.2. `COUNT(DISTINCT ...)` — количество разных значений

Один заказ может включать несколько товарных позиций.

Поэтому для подсчёта уникальных заказов используется:

```sql
SELECT COUNT(DISTINCT order_id)
FROM order_items
WHERE status = 'completed';
```

`DISTINCT` означает, что одинаковые значения `order_id` учитываются один раз.

Это напоминает `nunique()` в pandas.

**Важно:** `COUNT(DISTINCT order_id)` считает разные *непустые* идентификаторы. SQL не включает значения `NULL` в такой подсчёт.

Количество товарных позиций и количество уникальных заказов могут различаться — они измеряют разные вещи.

### 4.3. `SUM()` — сумма числовых значений

Если требуется узнать, сколько единиц товаров содержится в завершённых позициях:

```sql
SELECT SUM(quantity)
FROM order_items
WHERE status = 'completed';
```

`SUM(quantity)` суммирует значения количества.

Это аналогично:

`completed_df["quantity"].sum()`

А для расчёта учебной выручки используем формулу количества и цены:

```sql
SELECT SUM(quantity * unit_price)
FROM order_items
WHERE status = 'completed';
```

SQL рассчитывает `quantity * unit_price` для каждой выбранной товарной позиции, затем складывает результаты.

**Почему фильтр обязателен?**

Если забыть `WHERE status = 'completed'`, в сумму попадёт отменённая позиция 2006.

Тогда расчёт не будет соответствовать правилам учебной выручки.

Помните: выручка — не прибыль. Наш учебный расчёт не учитывает себестоимость, налоги, доставку, скидки и возвраты.

### 4.4. Коротко о `NULL`

В SQL `NULL` обозначает отсутствующее или неизвестное значение.

Это не то же самое, что число `0`.

Для поиска строк с отсутствующим количеством применяется:

```sql
SELECT line_item_id, order_id
FROM order_items
WHERE quantity IS NULL;
```

Для `NULL` используется `IS NULL`, а не `= NULL`.

В подготовленном исходном наборе «Северного света» пропущенных количеств нет, поэтому этот запрос не должен возвращать строк.

При этом отсутствие пропусков в одном столбце ещё не доказывает качество всей таблицы.

## 5. Разберём пример: первые показатели магазина

**Бизнес-запрос:**

> Сколько завершённых товарных позиций есть в «Северном свете», сколько разных завершённых заказов они представляют и какова их учебная выручка?

Разберём решение с помощью трёх коротких SQL-запросов.

### Шаг 1. Считаем завершённые позиции

```sql
SELECT COUNT(*)
FROM order_items
WHERE status = 'completed';
```

Ожидаемый результат: **9**.

Это количество строк товарных позиций, имеющих статус `completed`.

### Шаг 2. Считаем уникальные завершённые заказы

```sql
SELECT COUNT(DISTINCT order_id)
FROM order_items
WHERE status = 'completed';
```

Ожидаемый результат: **7**.

Почему число меньше девяти?

Потому что отдельные заказы содержат несколько позиций. Например, заказ 5001 включает кружки и блокноты, а заказ 5007 — лампу и бутылку.

### Шаг 3. Рассчитываем учебную выручку

```sql
SELECT SUM(quantity * unit_price)
FROM order_items
WHERE status = 'completed';
```

Ожидаемый результат: **10 650 рублей**.

Это сумма выручки всех девяти завершённых товарных позиций.

В зависимости от числового типа столбца `unit_price` PostgreSQL может отобразить итог как `10650` или `10650.00`. Числовой смысл результата одинаков.

### Формулируем аналитический вывод

«В рассматриваемом наборе данных есть девять завершённых товарных позиций, относящихся к семи уникальным заказам. Общая учебная выручка составляет 10 650 рублей. Отменённые позиции в расчёте не учитывались».

Это те же показатели, которые мы ранее рассчитывали с помощью pandas.

**Разница в инструменте:** теперь запрос выполняется PostgreSQL над таблицей базы данных, а не Python над DataFrame.

### Задание 1. Ваш первый SQL-запрос

**Уровень:** начальный  
**Ориентировочное время:** 8 минут

**Бизнес-вопрос:**

> Какие товарные позиции в магазине завершены и какое количество каждого товара указано в них?

Напишите SQL-запрос, который:
