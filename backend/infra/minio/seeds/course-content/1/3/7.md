## 1. От списков Python к таблицам pandas

В уроке 6 вы могли хранить несколько записей во вложенных списках и обрабатывать их циклом `for`. Это полезный способ понять алгоритм. Но когда таблица содержит множество строк и столбцов, удобнее работать с ней как с единым объектом.

**pandas** — библиотека Python, предоставляющая инструменты для чтения, исследования и обработки табличных данных. Библиотека — это готовый набор возможностей, которые можно подключить к программе.

```python
import pandas as pd

print("pandas подключён")
```

Результат:

```text
pandas подключён
```

Слово `import` подключает библиотеку. `as pd` задаёт ей короткое имя: далее вместо `pandas` можно писать `pd`. Библиотека уже установлена в учебной среде, устанавливать ничего не нужно.

### 1.1. DataFrame — таблица в памяти программы

**DataFrame** — объект pandas, похожий на таблицу: у него есть строки, столбцы и имена столбцов. Одна строка по-прежнему может означать товарную позицию, а столбец — количество, цену или статус.

Различайте три вещи:

- **CSV** — текстовый формат представления данных, где значения разделены специальным символом (в наших примерах запятой).
- **DataFrame** — таблица, с которой программа работает в оперативной памяти.
- **Таблица PostgreSQL** — данные, хранящиеся в базе; pandas не получает к ним доступ сам по себе.

В учебной песочнице нет файлов с заказами и нет подключения к базе данных. Поэтому мы будем помещать CSV-текст непосредственно в программу и передавать его pandas.

### 1.2. Загружаем первый CSV

Наша первая таблица содержит две строки с товарами. Это небольшой учебный пример, а не полный набор «Северного света».

```python
import pandas as pd
from io import StringIO

csv_text = """product,quantity
Mug,2
Notebook,3
"""

df = pd.read_csv(StringIO(csv_text))
print(df)
```

Результат:

```text
    product  quantity
0       Mug         2
1  Notebook         3
```

Разберём новые части:

1. `csv_text` хранит текст CSV. Тройные кавычки `"""` позволяют записать текст в несколько строк.
2. `from io import StringIO` подключает стандартный инструмент Python, который позволяет читать строку **как текстовый поток**, похожий для программы на открытый файл.
3. `StringIO(csv_text)` передаёт наш текст для чтения, **не создавая файл на диске**.
4. `pd.read_csv(...)` разбирает CSV и создаёт DataFrame.
5. `df` — переменная, в которой хранится полученная таблица; `print(df)` показывает её.

Числа `0` и `1` слева — индексы строк, добавленные pandas. Они **не** являются столбцом из CSV. В обычной работе также можно прочитать настоящий CSV-файл командой `pd.read_csv("имя_файла.csv")`, но **в нашей песочнице такого файла нет**, поэтому здесь используем `StringIO`.

## 2. Как исследовать DataFrame

Предположим, мы получили небольшую **отдельную тренировочную таблицу** из четырёх записей:

```python
import pandas as pd
from io import StringIO

csv_text = """product,quantity,unit_price,status
Mug,2,450,completed
Notebook,3,180,completed
Bottle,1,900,cancelled
Lamp,1,2400,completed
"""

df = pd.read_csv(StringIO(csv_text))

print("Первые две строки:")
print(df.head(2))
print("Размер:", df.shape)
print("Столбцы:", df.columns)
print("Типы:")
print(df.dtypes)
print("Количество по строкам:")
print(df["quantity"])
```

### 2.1. `head()` — первые строки

`df.head(2)` показывает первые **две** строки DataFrame. Без числа в скобках `df.head()` обычно показывает первые пять строк (если строк меньше пяти — все имеющиеся).

В нашем примере первые записи — Mug и Notebook. **`head()` не проверяет всю таблицу** и не показывает скрытые ниже ошибки.

### 2.2. `shape` — размеры таблицы

`df.shape` возвращает пару значений: **(число строк, число столбцов)**.

Для этой таблицы результат:

```text
(4, 4)
```

Здесь четыре товарные позиции и четыре столбца. Это **не** количество разных заказов: в таблице даже нет `order_id`.

### 2.3. `columns` — названия столбцов

`df.columns` показывает имена столбцов. В данном случае это `product`, `quantity`, `unit_price`, `status`.

Проверка полезна, если программа ожидает `quantity`, а в заголовке случайно написано другое имя. Для обращения к столбцу нужно использовать его точное название.

### 2.4. `dtypes` — как pandas понял типы

`df.dtypes` показывает тип данных каждого столбца. Для приведённого CSV pandas обычно определяет `quantity` и `unit_price` как целочисленные столбцы, а `product` и `status` — как текстовые (в некоторых версиях pandas текст отображается как `object`).

Здесь важен **смысл**, а не запоминание конкретного написания типа. Например, при загрузке CSV даты вроде `2026-09-01` обычно ещё не становятся специальным типом даты без дополнительного указания.

**Тип, автоматически выбранный pandas, нужно проверять:** программа не знает всех правил вашего бизнеса.

### 2.5. `df["имя_столбца"]` — один столбец

Выражение `df["quantity"]` выбирает столбец `quantity`. В показанном примере он содержит значения 2, 3, 1 и 1.

Это не то же самое, что `df["quantity"].sum()`: пока мы **только смотрим данные**, а не рассчитываем показатели. Отдельные столбцы pandas обычно представлены объектами Series; подробно изучать их устройство сегодня не требуется.

**Обратите внимание на запись команд:** `head()` и `dtypes` выглядят похоже, но `head()` вызывается с круглыми скобками, а `shape`, `columns` и `dtypes` используются без них. Первое — действие (метод), второе — свойства (атрибуты) объекта.

## 3. Первые проверки качества данных

Прежде чем считать выручку, нужно выяснить, все ли ожидаемые значения присутствуют и подходят ли они для расчёта.

### 3.1. Как увидеть пропуски

Рассмотрим ещё один **отдельный учебный CSV**, в котором у одного товара не указано количество:

```python
import pandas as pd
from io import StringIO

csv_text = """product,quantity,unit_price,status
Mug,2,450,completed
Notebook,,180,completed
Bottle,1,900,cancelled
Lamp,2,2400,completed
"""

df = pd.read_csv(StringIO(csv_text))

print("Размер:", df.shape)
print("Пропуски по столбцам:")
print(df.isna().sum())
print("Типы:")
print(df.dtypes)
```

Ключевые результаты:

```text
Размер: (4, 4)
Пропуски по столбцам:
product       0
quantity      1
unit_price    0
status        0
```

Метод `isna()` отмечает отсутствующие значения. Последующий `.sum()` подсчитывает их количество в каждом столбце. В нашем примере **один пропуск в `quantity`**, остальные столбцы полностью заполнены.

Из-за пропуска числовой столбец `quantity` может получить тип с дробной частью, например `float64`, хотя заполненные значения выглядят как целые. Это **не означает**, что в магазине допустимо продать 1,5 штуки: бизнес-правило осталось прежним.

**Пропуск — не ноль.** Мы не знаем, какое количество должно стоять у Notebook. Автоматически подставлять 0, удалять строку или рассчитывать её выручку без уточнения нельзя.

### 3.2. Сколько записей каждого статуса?

`value_counts()` считает, сколько раз встречается каждое значение выбранного столбца.

```python
import pandas as pd
from io import StringIO

csv_text = """line_item_id,order_id,status
2004,5003,completed
2005,5004,completed
2006,5005,cancelled
2007,5006,completed
"""

df = pd.read_csv(StringIO(csv_text))
print(df["status"].value_counts())
print("Разных заказов:", df["order_id"].nunique())
```

В этом фрагменте статусы встречаются так: **3 `completed` и 1 `cancelled`**. Метод `nunique()` считает число разных значений в столбце `order_id`: здесь **4 заказа**.

**Не путайте показатели:** `value_counts()` в столбце `status` подсчитывает **строки товарных позиций**, а `df["order_id"].nunique()` — **разные номера заказов**. При повторяющихся `order_id` результаты могут отличаться. `nunique()` здесь учитывает номера заказов всех статусов, в том числе отменённых; отбор завершённых заказов изучим позже.

### 3.3. Что проверять перед расчётами

Начальная проверка таблицы включает вопросы:

- Сколько строк и столбцов загрузилось? Совпадает ли это с ожиданиями?
- Есть ли необходимые названия столбцов?
- Какие типы pandas определил для количества, цены и даты?
- Есть ли пропуски в важных полях?
- Встречаются ли неожиданные статусы или подозрительные значения?
- Не противоречат ли записи правилам модели: уникальный `line_item_id`, положительное целое `quantity`, неотрицательная цена и согласованный статус внутри заказа?

Сегодня мы учимся **замечать** возможные проблемы. Исправлять их, фильтровать строки и массово рассчитывать показатели в pandas будем в следующих уроках.

## 4. Разберём короткую проверку CSV

Ниже — **отдельный тренировочный пример**, в котором есть пропуск и потенциальная проблема с типом данных:

```python
import pandas as pd
from io import StringIO

csv_text = """product,quantity,status
Mug,2,completed
Notebook,,completed
Lamp,3,cancelled
"""

df = pd.read_csv(StringIO(csv_text))
print(df.head())
print("Размер:", df.shape)
print("Типы:")
print(df.dtypes)
print("Пропуски:")
print(df.isna().sum())
```

**Перед запуском попробуйте предположить:** сколько строк и столбцов будет у таблицы, где обнаружится пропуск и каким типом pandas может представить `quantity`.

### Разбор результата

1. Заголовок определяет **три столбца**: `product`, `quantity`, `status`.
2. После заголовка находятся **три записи**; `shape` показывает `(3, 3)`.
3. У Notebook поле `quantity` пустое, поэтому `df.isna().sum()` показывает **один пропуск** в этом столбце.
4. Из-за отсутствующего значения pandas может представить `quantity` числовым типом с дробной частью, например `float64`.
5. Прежде чем рассчитывать количество товаров, нужно выяснить, какое значение отсутствует. Мы не подставляем его наугад.

Здесь мы сделали полезное аналитическое действие **до вычислений**: убедились, что структура прочитана правильно, и выявили ограничение данных.
