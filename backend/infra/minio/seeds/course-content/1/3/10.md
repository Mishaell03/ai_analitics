## 1. Почему данным нельзя доверять автоматически

Руководитель магазина сообщает:

> «Выручка за последние дни неожиданно выросла. Проверьте, действительно ли продажи увеличились».

Аналитик запускает правильную программу расчёта выручки. Но в исходной таблице обнаруживаются три проблемы:

- Одна отменённая позиция ошибочно включена в расчёт.
- У двух строк одинаковый идентификатор, который должен быть уникальным.
- В одной записи указано невозможное количество товара.

Python может успешно сложить эти значения. Однако полученный итог будет ненадёжным.

Поэтому до расчётов нужно понять, **соответствуют ли данные установленным правилам**.

### 1.1. Четыре важных свойства качества данных

| Свойство | Что проверяем | Пример |
|---|---|---|
| Полнота | Присутствуют ли обязательные значения | Не пропущено ли `quantity` |
| Уникальность | Не повторяются ли уникальные идентификаторы | Нет ли двух строк с одинаковым `line_item_id` |
| Допустимость | Соответствуют ли значения правилам | `quantity > 0`, `unit_price >= 0` |
| Согласованность | Не противоречат ли связанные записи друг другу | Одинаковы ли дата, клиент и статус внутри одного заказа |

В нашей учебной модели:

- Каждая строка — одна товарная позиция.
- `line_item_id` должен быть уникальным.
- `order_id` может повторяться, если заказ содержит несколько позиций.
- Количество должно быть положительным целым числом.
- Цена не может быть отрицательной.
- Допустимы статусы `completed` и `cancelled`.
- Строки одного заказа должны относиться к одному клиенту, дате и статусу.

### 1.2. Ошибка или повод для уточнения?

Не все необычные значения следует автоматически исправлять.

Например:

- `quantity = 0` нарушает правила нашей учебной модели.
- Повторяющийся `line_item_id` нарушает требование уникальности.
- Повторяющийся `order_id` может быть совершенно правильным.
- Неожиданно высокая цена может оказаться реальной, а не ошибочной.
- Неизвестный статус может означать, что исходная система использует дополнительные значения.

**Обнаружить проблему — не значит сразу удалить строку.**

Сначала следует установить причину, уточнить необходимые данные и только после этого принимать обоснованное решение.

**От исходных данных к надёжному анализу:** исходная таблица → проверка качества → анализ проверенных данных. Пропуски, повторы уникального идентификатора и неизвестные статусы требуют проверки: обнаружить → проверить → принять обоснованное решение.

## 2. Проверяем качество данных с помощью pandas

### 2.1. Ищем пропущенные значения

В уроке 7 вы познакомились с `isna().sum()`. Теперь используем эту проверку для конкретной задачи.

Перед вами **отдельный тренировочный набор**, специально содержащий пропуск. Он не изменяет исходные данные магазина.

```python
import pandas as pd
from io import StringIO

csv_text = """line_item_id,order_id,quantity,unit_price,status
4101,6101,2,450,completed
4102,6101,,180,completed
4103,6102,1,900,cancelled
"""

df = pd.read_csv(StringIO(csv_text))

print("Пропуски по столбцам:")
print(df.isna().sum())

print("Строки с пропущенным количеством:")
print(df[df["quantity"].isna()])
```

**Что обнаружит программа?**

- В таблице три записи.
- В столбце `quantity` имеется один пропуск.
- Пропуск находится в позиции 4102.
- Остальные столбцы не содержат пропусков.

В числовом столбце pandas обычно отображает отсутствующее значение как `NaN` — специальное обозначение пропуска.

Поскольку в `quantity` есть отсутствующее значение, pandas может определить тип всего столбца как `float64`, хотя заполненные количества являются целыми числами.

**Важно:** пропущенное количество не равно нулю.

Мы не знаем, сколько единиц товара было в позиции 4102. Нельзя подставлять ноль только ради успешного выполнения расчёта.

Кроме того, некоторые числовые операции pandas, включая `.sum()`, по умолчанию пропускают отсутствующие значения. Поэтому программа может вывести число, даже если исходные данные неполные.

### 2.2. Находим повторяющиеся идентификаторы

Рассмотрим другой тренировочный набор:

```python
import pandas as pd
from io import StringIO

csv_text = """line_item_id,order_id,product
4201,6201,Mug
4202,6201,Notebook
4202,6202,Lamp
"""

df = pd.read_csv(StringIO(csv_text))

duplicate_mask = df["line_item_id"].duplicated(keep=False)

print("Результаты проверки:")
print(duplicate_mask)

print("Подозрительные записи:")
print(df[duplicate_mask])
```

Результат проверки:

```text
0    False
1     True
2     True
Name: line_item_id, dtype: bool
```

Новый метод `duplicated()` определяет повторяющиеся значения.

Параметр `keep=False` означает: **отметить все вхождения повторяющегося значения**, а не только второе или последующие.

Поэтому обе строки с `line_item_id = 4202` получают `True`.

Затем `df[duplicate_mask]` выбирает эти строки для просмотра.

Обратите внимание:

- `line_item_id = 4202` повторяется — это подозрительно.
- `order_id = 6201` тоже повторяется — но это допустимо, поскольку заказ может содержать несколько разных товаров.

**Не следует автоматически удалять повторяющиеся `order_id` или одну из строк с одинаковым `line_item_id`.** Сначала нужно выяснить, откуда взялись эти записи.

### 2.3. Проверяем количество, цену и статус

Теперь рассмотрим ещё один **отдельный тренировочный набор**.

```python
import pandas as pd
from io import StringIO

csv_text = """line_item_id,quantity,unit_price,status
4301,2,450,completed
4302,0,180,completed
4303,1,-900,cancelled
4304,1,900,processing
"""

df = pd.read_csv(StringIO(csv_text))

print("Недопустимое количество:")
print(df[df["quantity"] <= 0])

print("Отрицательная цена:")
print(df[df["unit_price"] < 0])

print("Неизвестные статусы:")
print(
    df[
        (df["status"] != "completed")
        & (df["status"] != "cancelled")
    ]
)
```

Что мы обнаружили:

- Позиция 4302: количество равно нулю.
- Позиция 4303: цена отрицательная.
- Позиция 4304: статус `processing` не входит в два допустимых значения.

Почему для количества используется `<= 0`, а для цены `< 0`?

По правилам магазина:

- Количество должно быть **строго больше нуля**.
- Цена может равняться нулю, но не может быть отрицательной.

Неожиданный статус мы определяем с помощью двух сравнений: значение не равно ни `completed`, ни `cancelled`.

Оператор `&` означает, что оба условия должны выполняться одновременно.

Обратите внимание, что одна запись может нарушать **несколько правил сразу**. Поэтому нельзя считать количество найденных ошибок количеством разных проблемных строк без дополнительной проверки.

### 2.4. Проверяем типы данных

Иногда проблема заключается не в самом числе, а в способе его записи.

Например:

```python
import pandas as pd
from io import StringIO

csv_text = """line_item_id,quantity
4401,2
4402,two
4403,1
"""

df = pd.read_csv(StringIO(csv_text))

print(df.dtypes)
```

Значение `two` представляет собой текст, а не целое число.

Из-за него pandas может определить весь столбец `quantity` как `object`, а не числовой тип.

Если попытаться использовать такие значения в обычных арифметических операциях, результат может оказаться ошибочным или операция вообще не выполнится.

**Не следует автоматически считать, что `two` означает 2, и заменять его без проверки источника.**

Сначала необходимо выяснить, какое значение действительно должно находиться в записи.

## 3. Описательная статистика: что можно узнать о числах

Проверка качества помогает понять, можно ли использовать данные.

Следующий шаг — описать числовые значения с помощью нескольких понятных показателей.

**Описательная статистика** помогает кратко охарактеризовать имеющиеся данные. Сегодня познакомимся с четырьмя показателями.

| Показатель | Значение | Метод pandas |
|---|---|---|
| Среднее арифметическое | Сумма значений, делённая на их количество | `.mean()` |
| Медиана | Середина упорядоченного набора значений | `.median()` |
| Минимум | Наименьшее значение | `.min()` |
| Максимум | Наибольшее значение | `.max()` |

### 3.1. Среднее и медиана — не одно и то же

Рассмотрим **отдельный тренировочный набор** количеств товаров:

```python
import pandas as pd
from io import StringIO

csv_text = """line_item_id,quantity
6101,1
6102,2
6103,2
6104,3
6105,12
"""

df = pd.read_csv(StringIO(csv_text))

print("Среднее:", df["quantity"].mean())
print("Медиана:", df["quantity"].median())
print("Минимум:", df["quantity"].min())
print("Максимум:", df["quantity"].max())
```

Результат:

```text
Среднее: 4.0
Медиана: 2.0
Минимум: 1
Максимум: 12
```

**Почему среднее равно 4?**

Складываем значения и делим на их количество:

`(1 + 2 + 2 + 3 + 12) / 5 = 20 / 5 = 4`.

**Почему медиана равна 2?**

Упорядочиваем значения:

`1, 2, 2, 3, 12`

В середине находится третье значение — 2.

Если значений чётное количество, медианой будет среднее двух центральных значений. Например, для `1, 2, 3, 10` медиана равна `(2 + 3) / 2 = 2,5`.

### 3.2. Как необычно большое значение влияет на результат

В нашем примере четыре количества находятся между 1 и 3, а последнее равно 12.

Из-за этого среднее поднялось до 4, хотя медиана осталась равной 2.

**Медиана меньше зависит от отдельных очень больших или очень маленьких значений, чем арифметическое среднее.**

Но количество 12 само по себе не является ошибкой. Вполне возможно, что покупатель действительно заказал 12 единиц товара.

Поэтому необычное значение сначала нужно исследовать, а не удалять ради более удобной статистики.

Помните:

- Среднее и медиана описывают данные по-разному.
- Статистика не объясняет автоматически, почему значения именно такие.
- По необычно большому числу нельзя без дополнительных сведений делать вывод о его ошибочности или причине появления.

### 3.3. Статистика по завершённым позициям «Северного света»

Вернёмся к **исходным десяти записям магазина**, но используем только необходимые для этого расчёта столбцы: `line_item_id`, `quantity` и `status`.

Значения этих полей полностью соответствуют основной таблице.

```python
import pandas as pd
from io import StringIO

csv_text = """line_item_id,quantity,status
2001,2,completed
2002,3,completed
2003,1,completed
2004,2,completed
2005,5,completed
2006,1,cancelled
2007,1,completed
2008,1,completed
2009,1,completed
2010,2,completed
"""

df = pd.read_csv(StringIO(csv_text))
completed_df = df[df["status"] == "completed"]

print("Завершённых позиций:", len(completed_df))
print("Продано единиц:", completed_df["quantity"].sum())
print("Среднее:", completed_df["quantity"].mean())
print("Медиана:", completed_df["quantity"].median())
print("Минимум:", completed_df["quantity"].min())
print("Максимум:", completed_df["quantity"].max())
```

Результат:

```text
Завершённых позиций: 9
Продано единиц: 18
Среднее: 2.0
Медиана: 2.0
Минимум: 1
Максимум: 5
```

### Как правильно интерпретировать результат?

В девяти завершённых товарных позициях продано 18 единиц товаров.

**В среднем на одну завершённую товарную позицию приходилось 2 единицы товара.**

Медианное количество также равно двум.

Но это **не означает**, что в среднем один заказ содержал две единицы. Для показателя на заказ необходимо отдельно учитывать уникальные `order_id` и объединять относящиеся к ним позиции.

Также не следует путать среднюю цену единицы товара по строкам таблицы со средней ценой реально проданной единицы: позиции могут содержать разное количество товаров.
